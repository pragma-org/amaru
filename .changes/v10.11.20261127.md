## [v10.11.20261127](https://github.com/pragma-org/amaru/releases/tag/v10.11.20261127)

### Added

- **amaru**: `amaru pool create` generates cold keys and an issue counter offline, with optional payment and owner/reward stake key pairs. Prints the pool ID and generated verification keys and addresses as JSON to stdout; payment keys without stake keys produce an enterprise address with no staking rights. Existing output files are never replaced.
- **amaru**: generate pool cold keys and an issue counter offline with `amaru pool cold create`, then create operational certificates with `amaru pool cert create`. Keys are raw bytes; counters and certificates are binary CBOR. Legacy cardano-cli envelopes remain accepted as inputs.
- **amaru**: `amaru transaction sign` signs binary CBOR Conway transactions offline with one or more payment, stake, or pool cold signing keys, supplied as raw 32-byte seeds or cardano-cli text envelopes.
- **amaru-node**: embedded applications can submit transactions, inspect mempool contents, and subscribe to insertion and removal events. Slow subscribers are notified when they miss events.
- **amaru-consensus**: `cardano_node_metrics_forks_counter` counts the times the adopted chain switched to a fork and rolled back at least one block. The metric appears after the first such switch.
- **amaru-protocols**: the connection manager reports `cardano_node_metrics_connectionManager_duplexConns_int`, the number of connections whose handshake agreed on full duplex.
- **amaru-consensus**: block propagation is reported with the cardano-node metric names. `cardano_node_metrics_blockfetchclient_blockdelay_real` is the time in seconds from a block's slot start to the reception of its body. `cardano_node_metrics_blockfetchclient_blockdelay_cdfOne_real`, `cdfThree_real` and `cdfFive_real` are the shares of recent blocks received within 1, 3 and 5 seconds. `cardano_node_metrics_blockfetchclient_lateblocks_counter` counts blocks received more than 5 seconds after their slot start. As in cardano-node, blocks are ignored after startup until one arrives within 20 seconds of its slot start, and every fetched block counts after that. The shares cover the last k/2 blocks. The shares appear once 45 blocks have been measured.

### Changed

- **amaru**: block propagation lines include the block slot and height. `block.received` also includes the raw block size in bytes. `tip.adopt` includes `adopt_kind`: `roll_forward` or `fork_switch`.
- **amaru**: `header.announced`, `block.requested`, `block.received`, and `block.adopted` are always debug, including while the node is live. `block.adopted` is recorded for every block placed on the best chain, including the blocks between a fork and the new tip. `tip.adopt` logs only the new tip: while syncing, at most one info line per second; once live, one info line per block.
- **amaru**: `node run` logs `node.run` at info once the peer listener is bound and, when enabled, the submit API has bound. The line names this binary's version, the node-to-node versions offered, the network, and the node-to-node listen addresses. `submit_api` is the address that API bound, and is omitted when the API is disabled. Port 0 is replaced by the assigned port. A failed submit API bind does not emit this line. The versions and listen addresses are lists. The configuration dump stays on the `amaru::cli` span of the same name.
- **amaru**: a completed handshake logs the negotiated node-to-node version, whether diffusion is initiator-only, and whether peer sharing is enabled. `connection_died_handled` includes `conn_id`. Orderly shutdown of `node run` logs `lifecycle.shutdown` with `reason=node_restart` before connections are closed.
- **amaru**: `amaru pool schedule inspect` also reports the pool id and the epoch nonce the schedule was computed with.
- **amaru-protocols**: `connection.handshake_refused` and `connection.handshake_query_reply` carry `peer`, `conn_id` and `role`, so a refused handshake can be traced to a remote address and a direction. ([#1634](https://github.com/pragma-org/amaru/issues/1634))
- **amaru**: loading a legacy cardano-cli text envelope emits `envelope.legacy` under `amaru::io` at trace level with its envelope type and path, including VRF keys, certificates, and counters. Raw key and binary CBOR files do not emit this event.

### Fixed

- **amaru-node**: mempool validation now carries each accepted transaction's ledger state into the next validation, preventing conflicting transactions from being admitted together and allowing valid transaction chains.
- **amaru-consensus**: only block producers report `cardano_node_metrics_currentKESPeriod_int`, from the wall-clock KES period of their forging key. Relays no longer export it, so monitoring tools no longer show KES information for a node that cannot forge.
- **amaru**: `node run` can start on macOS when the system DNS configuration includes an IPv6 nameserver with an interface suffix such as `%en0`.
- **amaru**: `chainsync.chain_lagging` is no longer logged for a node at the tip when two checks in a row fall in a long gap between blocks. The check stays quiet once the adopted tip has reached the height of the header seen at the previous check. ([#1631](https://github.com/pragma-org/amaru/issues/1631))
- **amaru-consensus**: chain selection breaks a tie between two tips of the same height on the VRF output of the header, as cardano-node does, instead of on the leader value derived from it. ([#1650](https://github.com/pragma-org/amaru/issues/1650))
- **amaru-node**: the HTTP submit API rejects transaction bodies larger than 64 KiB with 413, rejects trailing CBOR data with 400, and returns 503 when the node has stopped.
